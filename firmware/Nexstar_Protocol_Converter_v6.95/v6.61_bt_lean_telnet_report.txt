Nexstar Protocol Converter v6.61 report

Baseline:
- v6.60 BT Telnet menu heap guard.

Issue:
- In BT mode, even Telnet status/menu activity could freeze or make access unreliable.
- v6.60 serial evidence showed BT + WiFi + Telnet had very tight heap and stack margin.

Root cause:
- Runtime-disabling Web/protocol services does not reclaim RAM already reserved by global Telnet UI buffers.
- BT mode still had the full-screen Telnet UI available when heap looked briefly healthy.
- The full status command printed a large report with several String conversions and long formatted lines.

Changes:
- BT mode now disables full-screen Telnet UI unconditionally:
  - menu / ui
  - monitor
  - tasks
  - live Telnet logging
- Telnet help now reports that full Telnet UI is disabled in BT mode.
- Telnet status in BT mode now uses a small direct "BT Lean Status" report.
- Telnet runtime status in BT mode avoids the password String builder and includes heap diagnostics.
- Reduced always-allocated Telnet command history from 12 entries to 6.
- Reduced always-allocated Telnet menu capture buffers from 4096 bytes each to 1536 bytes each.

Expected memory effect:
- Global RAM use should drop by roughly 5 KB from the two menu page buffers plus a smaller command history footprint.
- BT mode avoids the highest-risk Telnet UI/status paths while keeping the plain command console.

Files changed:
- Nexstar_Protocol_Converter_v6.61.ino
- network_services.cpp

Build target:
- esp32:esp32:esp32:PartitionScheme=huge_app
